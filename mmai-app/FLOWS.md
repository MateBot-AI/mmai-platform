## Review hardening checks (31 October 2026, second pass on the submission key)
- Durable one enquiry per key: `enquiries.submission_key` (additive nullable column, UNIQUE index `ux_enq_submission_key`) is written in the same INSERT as the enquiry row, so the database itself refuses a second enquiry for one key even if the application checks were bypassed; enquiries made without a key (staff tools, seed, legacy clients) have NULL and never collide.
